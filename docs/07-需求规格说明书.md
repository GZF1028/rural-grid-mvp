# 07-需求规格说明书（SRS）

> 项目：数字乡村网格化后台（rural-grid-mvp）
> 线上：https://rural-grid-mvp-production.up.railway.app
> 版本：v1.0（试岗交付版）
> 说明：本文档描述**已实现**的功能规格，作为验收与交接依据。

## 1. 文档目的与范围

- 目的：把口述需求固化为**可验收的需求条目（FR/NFR）**，明确页面、字段、校验、状态与验收标准。
- 范围：重点人群档案、走访记录、网格地图（展示/编辑/持久化）、部署。
- 不在范围：登录/权限、事件管理、通知、统计报表、GIS 精度（见第 9 节）。

## 2. 项目背景与目标

数字乡村场景下，网格员需要管理「重点人群」档案，并在地图上查看/调整各网格（上河组/下河组/桥头组）范围。目标是用一个**无登录、单操作人**的迷你后台，跑通「档案筛选 → 新增/修改 → 详情与走访 → 地图编辑持久化」的闭环。

## 3. 用户角色与典型场景

| 角色 | 说明 | 场景 |
|---|---|---|
| 网格员（默认操作人） | 无需登录，默认当前网格员 | 筛选待走访人群、登记走访、维护档案 |
| 村干部（查看/演示） | 查看档案、走访记录、网格范围 | 了解谁在哪个网格、风险、最近走访 |

**典型场景**：
1. 筛选「上河组 + 高风险」→ 查看档案 → 新增走访记录。
2. 新增留守儿童档案（填监护人姓名 + 监护人手机号）。
3. 在地图上拖拽上河组边界 → 保存 → 刷新后边界仍在，档案归属不变。

## 6. 状态机

```
Person.status:
  NORMAL（正常） ──手动──▶ KEY_FOCUS（重点关注）
  NORMAL ──手动──▶ PENDING_VISIT（待走访）
  PENDING_VISIT ──新增走访（系统）──▶ NORMAL
  KEY_FOCUS ──手动──▶ NORMAL / PENDING_VISIT
```

规则：
1. 状态由人手动设置；
2. 新增走访记录时：若当前为 `PENDING_VISIT`，自动置为 `NORMAL`；
3. 新增走访后，`last_visit_at` 更新为该人所有走访中最大的 `visited_at`。

## 7. 校验规则汇总

| 规则 | 适用 | 报错文案 |
|---|---|---|
| 姓名非空 | 表单 | 请填写姓名 |
| 网格必选 | 表单 | 请选择所属网格 |
| 手机号格式 `^1[3-9]\d{9}$` | 表单 | 手机号格式不正确 |
| 留守儿童监护人必填 | 表单 | 留守儿童请填写监护人姓名 |
| 走访摘要有必填 | 走访弹窗 | 请填写情况摘要 |
| 走访人必填 | 走访弹窗 | 走访人不能为空 |
| 边界格式（Polygon） | 保存地图 | 边界格式不合法 |

## 8. 非功能需求（NFR）

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-01 | 响应式 | 375px 下列表为卡片、**无横向滚动**；地图可展示；编辑桌面优先 |
| NFR-02 | 性能 | 列表 10~100 条内秒开；地图首屏 2s 内出现多边形 |
| NFR-03 | 兼容 | Chrome/Edge 最新版；地图依赖高德瓦片网络 |
| NFR-04 | 持久化 | 数据落 PostgreSQL（Neon），刷新/重启不丢 |
| NFR-05 | 部署 | 公开 URL（Railway），单服务托管前端 + API |
| NFR-06 | 安全 | 手机号脱敏；`.env` 不入库；无登录但默认单操作人 |
| NFR-07 | 可维护 | 前后端分离、类型安全（TS/Prisma/Zod）、文档齐全（docs/01-07） |

## 9. 不做清单（明确排除）

登录/权限/多角色/多租户；短信、支付、文件上传；事件管理、数据分析、系统设置；通知中心；天气数据接入；快捷操作按钮；GIS 精度/官方行政区划/多图层/轨迹/面积自动测量。
