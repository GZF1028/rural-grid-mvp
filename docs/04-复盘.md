# 04-复盘（3 天试岗闭环总结）

> 项目：数字乡村网格化后台（重点人群档案 + 网格地图）
> 线上地址：https://rural-grid-mvp-production.up.railway.app
> 仓库：https://github.com/GZF1028/rural-grid-mvp

## 一、目标达成情况（对照 A2 硬性闭环）

| 硬性要求 | 状态 | 证据 |

## 二、关键产品取舍（做了什么、砍了什么）

### 做了什么（MVP）
1. **重点人群档案**：列表（搜索/网格/风险/类型/状态筛选 + 分页）、新增/编辑、详情。
2. **走访记录**：独立子表，时间线展示；新增走访后自动刷新「最近走访时间」，并把「待走访」转「正常」。
3. **网格地图**：三网格展示、选中高亮、拖顶点/边中点编辑、保存持久化、普通/卫星底图切换、气泡标签。
4. **手机号脱敏**：列表/详情统一 `138****1246`；儿童用监护人手机号 + 监护人姓名。

### 砍了什么（明确不做）
- 登录/权限/多角色/多租户；短信、支付、文件上传；
- 事件管理、数据分析、系统设置、通知中心、天气数据接入；
- 快捷操作按钮、通知铃铛（设计图有，但非 MVP，**未实现即从界面移除**）；
- GIS 精度、官方行政区划导入、多图层、轨迹、面积自动测量。

### 三个关键取舍及理由
1. **地图用 Leaflet + 高德瓦片，而不是高德官方 SDK**：试岗优先保闭环，官方 SDK 要实名 Key + 重写地图引擎，收益不匹配；瓦片方案零成本、可演示，**生产环境会替换**。
2. **档案通过 `grid_id` 关联网格实体，而不是把坐标写进档案**：改边界只更新 `grid` 表，档案不受影响，直接满足"改完档案里的网格别乱"。
3. **风险等级手动枚举（高/中/低）**：无历史数据支撑自动算法，手动 + 颜色徽标直观、可演示、零过度设计。

## 三、技术实现要点

| 层 | 选型 |
|---|---|
| 前端 | React 18 + Vite + TypeScript + Tailwind CSS |
| 地图 | Leaflet + leaflet-geoman-free + 高德栅格瓦片（免 key） |
| 后端 | Node + Fastify + Prisma + Zod |
| 数据库 | PostgreSQL（Neon 免费档，真实持久化） |
| 部署 | Railway（单服务：后端托管前端 `dist` + API） |

- REST 接口：`GET/PUT /api/grids`、`GET/POST/PUT /api/persons`、`GET/POST /api/persons/:id/visits`。
- Zod 校验：手机号格式、留守儿童监护人必填、枚举值。
- 构建：`build:deploy` = `web build && server build`，server build 内 `prisma generate && tsc`。
- 部署：`railway.json` 指定 build/start，`PORT` 由 Railway 注入，`DATABASE_URL` 在 Railway Variables 配置。

## 四、踩坑与解决（真实过程）

| 坑 | 现象 | 解决 |
|---|---|---|
| pnpm 11 构建白名单 | `ERR_PNPM_IGNORED_BUILDS`（esbuild/prisma 脚本被拦） | `pnpm-workspace.yaml` 配 `allowBuilds` 放行 |
| 端口冲突 | 3000 被本机其它服务占用 | 后端改 4000，Vite 代理同步 |
| Vite watcher 崩溃 | 写文件时 `.tmpdir` 临时文件被 watch 报 `EBUSY` | `server.watch.usePolling + ignored` |
| 地图不显示 | 骨架屏期间容器不存在，init effect 只跑一次 | init effect 依赖 `loading`，容器渲染后再初始化 |
| Railway 构建缺 Prisma Client | `Gender` 等类型全缺失，tsc 报一堆错 | build 里显式 `prisma generate && tsc` |
| API 500 | `Environment variable not found: DATABASE_URL` | Railway Variables 配 `DATABASE_URL`（去掉 `channel_binding`） |
| CARTO 底图要 Key | 出现 `API KEY REQUIRED` 水印 | 换高德瓦片 `webrd`/`webst` |
| 出生日期/年龄 | 需要能填年龄 | 出生日期与年龄双向联动，年龄换算出生日期 |

## 五、AI 使用说明

- **生图**：豆包图片生成，2 方向 × 2 张（详见 `docs/02`），用于确定设计基准；**未使用 v0/Lovable 等代码生成工具替代设计图**。
- **编码**：AI 辅助完成前后端代码，但代码结构清晰、可解释（Prisma schema、REST 路由、React 组件、Leaflet/GeoMan 集成、部署配置），关键逻辑（网格与档案解耦、走访闭环、脱敏、校验）均为可讲清楚的实现。
- **文档**：需求收敛、设计基准、还原自查、复盘均为结构化整理，非直接套模板。

## 六、不足与改进方向

1. **地图边界仍是手绘演示坐标**，未贴合真实道路/田埂；任务允许，但若上线需接入真实行政区划或人工描图。
2. **高德瓦片为免 key 非官方用法**，正式产品应改用高德官方 SDK + Key（或天地图/腾讯官方方案），并补齐 Key 管理与配额。
3. **移动端编辑未做**（桌面优先），可补触摸拖拽或表单化编辑。
4. **缺少自动化测试**（单测/E2E），当前靠手工 + 脚本截图验证；生产化建议补 Playwright E2E。
5. **错误处理较基础**：可补全统一错误码、重试、请求取消等。
6. **设计还原是"观感级"而非像素级**：AI 插画底图与真实地图存在本质差异，统计数字用真实种子数据（与设计图示例数字不同）。

## 七、试岗总结

3 天内完成了「需求收敛 → AI 生图 → 设计基准 → 前端高保真 → 真实后端 → 地图编辑持久化 → 部署上线 → 复盘」的完整闭环，线上可访问、可演示、数据真实落库。

最大的收获是**取舍能力**：面对模糊口述需求，先收敛出最小可演示闭环，再逐层加厚；对设计图里"看着好看但不属于 MVP"的元素（快捷操作、通知、天气数据）主动砍掉并说明理由，而不是为了还原而堆功能。

余量时间下优先做的是「让评委能点、能信」的事：地图编辑持久化、真实后端、部署 URL、差异清单——而不是把 UI 做得更花。
